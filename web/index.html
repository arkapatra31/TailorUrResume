How it works

Six steps from posting to PDF.

Each step is one stateless API call. The browser holds the state and sends it with every request.

  1. 1

    Key

    Pick Anthropic or Ollama and test the connection. The key stays in memory and travels only in the X-LLM-Key header.

    /api/test-connection
  2. 2

    Profile

    Drop a PDF or DOCX. It is parsed in memory into an editable profile of experience, skills and education.

    /api/profile/parse
  3. 3

    Job

    Paste the posting, or fetch it from LinkedIn, Greenhouse, Lever or any careers page.

    /api/jd/fetch · /api/jd/extract
  4. 4

    Match

    Keyword coverage (must-haves count 3×) blended 55/45 with semantic fit, plus gaps and next steps.

    /api/match · /api/bridge
  5. 5

    Craft

    Stream a resume, CV or cover letter. Edit inline, regenerate single bullets, and diff against the original.

    /api/generate (SSE)
  6. 6

    Export

    Choose a Classic, Modern or Compact ATS-friendly template and download PDF or DOCX.

    /api/export/{pdf,docx}

Skill bridge

A missing keyword isn't always a missing skill.

For each job skill your resume doesn't name, the bridge checks whether experience you already have demonstrates it. You approve what goes in. Approved skills are worked in by rephrasing your existing wording, never by inventing bullets or achievements.

Evidence must literally appear in your profile. If the model invents evidence, the verdict collapses to unsupported.

Truthfulness guard

Every draft is checked against what you actually wrote.

After each generation the guard flags anything it can't trace back to your profile, so you can fix it before you send.

  • Technologies and job-description terms you never listed
  • Metrics, numbers and "N years of experience" claims
  • Proper nouns, job headers and dates that don't match
  • Contact lines that differ from your profile

The guard is heuristic. It reduces fabrication risk, but you should still read the result.

Private by design

Nothing to breach, because nothing is kept.

Your resume and the job text go only to the LLM provider you choose. Nothing else keeps them.

Stateless server

No database, disk writes, sessions or caches. Uploads are parsed in memory and exports are built in BytesIO. In Docker the API runs read-only.

Key never stored

Sent per request in a header and used to build a client for that request only. A log filter redacts it, and it is never echoed back.

Browser stores nothing

No localStorage, sessionStorage or cookies. Refreshing the tab clears everything, with a warning before you lose unsaved work.

Sessions on your terms

Save a session as a JSON file, without the key, and load it later to pick up where you left off.

Get started

Running in about a minute.

Bring an Anthropic API key, or pull a model into Ollama.

# clone and run: UI on :3000, API on :8000
git clone https://github.com/arkapatra31/TailorUrResume.git
cd TailorUrResume
docker compose up --build

# optional: also start a local Ollama
docker compose --profile ollama up --build
docker compose exec ollama ollama pull llama3.1
# backend (Python 3.11+)
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000

# frontend, in a new terminal: http://localhost:5173
cd frontend
npm install
npm run dev

PDF export needs Pango (brew install pango on macOS). Without it, DOCX export still works.
